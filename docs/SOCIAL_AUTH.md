# 카카오·네이버 로그인 연결

2026-11-01 기준 카카오 로그인은 운영에서 활성화했습니다. 카카오 REST API 키·Client Secret은 Worker Secret에 저장하며 레포와 브라우저 코드에는 포함하지 않습니다. 네이버 로그인은 비활성화 상태이며, 톡캘린더는 지정 계정의 연결 테스트만 허용합니다. [톡캘린더 설정과 검수](KAKAO_CALENDAR_SETUP.md)를 참고하세요. `VITE_AUTH_API_URL`이 없거나 서비스의 `/config`에 제공자가 비활성으로 표시되면 해당 로그인 버튼은 나오지 않습니다. 기존 Google 로그인은 그대로 사용할 수 있습니다.

## 등록 순서

1. 현재 인증 서버는 `https://moim-auth.moim-auth-worker.workers.dev`입니다. 새 프로젝트에 연결할 때는 [인증 서비스 안내](../services/auth-worker/README.md)에 따라 별도 서버를 준비합니다.
2. [Kakao Developers](https://developers.kakao.com/docs/latest/ko/kakaologin/prerequisite)에서 앱을 등록하고 카카오 로그인을 활성화합니다. 서비스 README에 지정된 실제 Worker 콜백 주소를 Redirect URI로 등록합니다. REST API 키와 Client Secret은 Worker의 비밀 설정에만 넣습니다.
3. [네이버 Developers](https://developers.naver.com/docs/login/register/register.md)에서 네이버 로그인 애플리케이션을 등록합니다. 서비스 URL은 실제 사이트 주소, Callback URL은 서비스 README의 실제 Worker 콜백 주소로 설정합니다. Client ID와 Client Secret은 Worker에만 둡니다.
4. Worker에 허용할 사이트 origin, 실제 인증 서비스 주소, Firebase 인증 설정과 각 제공자의 키를 입력하고 배포합니다. 현재 서버에는 Firebase/SOLAPI/카카오 로그인 설정이 등록돼 있으며 네이버 로그인 키 등록이 남아 있습니다.
5. `/config`에서 사용할 제공자만 활성으로 반환하는지 확인한 뒤 프런트엔드의 `VITE_AUTH_API_URL`을 실제 인증 서비스 URL로 설정하고 다시 빌드합니다.

Kakao JavaScript 키는 기존 카카오톡 공유용 설정입니다. 카카오 로그인용 REST API 키·Client Secret과 서로 다른 설정이며, 네이버 Client Secret을 포함한 비밀키를 `VITE_` 변수나 브라우저 코드에 넣으면 안 됩니다.

## 로그인과 기존 계정 연결

- 로그인 화면의 카카오·네이버 버튼은 서비스에서 실제 활성화한 제공자만 표시합니다.
- 기존 멤버는 원래 계정으로 로그인한 뒤 **내 정보 → 계정 → 연결**에서 다른 로그인 방식을 연결합니다. 연결은 현재 Firebase UID에 묶이며, 다른 계정의 정보를 자동으로 합치지 않습니다.
- 새 소셜 계정은 서비스가 가입 승인 대기 상태로 만듭니다. 이후 관리자의 승인이 필요합니다.
- 가입 정보에서 이름·전화번호·거주 지역·월일 생일을 모두 입력합니다. 정보가 누락된 기존 계정도 다음 접속 때 보완합니다. 휴대폰 번호 형식만 확인하며 SMS 본인 인증은 하지 않습니다. 저장 후 승인 대기 계정은 열람만 할 수 있습니다.
- 카카오가 이름을 제공하지 않으면 본인 이름을 직접 입력합니다. 제공된 실명·프로필 닉네임·기존 프로필 이름 순서로 확인하며, 이미 사용자가 저장한 이름은 이후 로그인으로 덮어쓰지 않습니다. 예전 `새 멤버` 기본값은 이름 정보가 다시 제공되면 복구하고, 없으면 가입 정보에서 입력받습니다.
- 공유받은 투표·일정은 로그인 및 가입 정보 저장 후 해당 화면으로 돌아갑니다. 소셜 인증 시 같은 브라우저의 일회용 요청에 허용된 투표·일정 경로만 저장합니다. 외부 주소, 인증 토큰과 무관한 쿼리는 넘기지 않습니다. 카카오 인앱 브라우저에서 외부 브라우저로 열거나 복사할 때도 같은 방식으로 공유 대상을 유지합니다.
- Google 계정이 없는 소셜 로그인 사용자는 내 정보에서 Google을 연결할 수 있습니다. 이미 다른 계정에 쓰인 Google 인증 정보는 자동 병합하지 않습니다.

인증 요청은 브라우저의 암호학적 난수와 SHA-256 challenge로 연결합니다. 브라우저에는 짧게 유지되는 verifier만 `sessionStorage`에 두고, 제공자의 Client Secret·access token·refresh token은 저장하지 않습니다. 콜백 교환 코드는 한 번만 사용하고, 연결 시 현재 Firebase ID token 및 UID를 다시 확인합니다.

## 가입 정보 자동 입력

- Google은 Firebase Auth의 계정 이름·로그인 제공자 이름을 가입 화면의 초기값으로 사용합니다. 로그인 정보에 전화번호가 있으면 함께 채웁니다. 추가 Google 개인정보 권한을 요청하지 않으며 전화번호·생일·거주 지역이 항상 제공되는 것은 아닙니다.
- 카카오는 제공되는 이름 또는 닉네임을 사용합니다. 동의받아 제공된 전화번호와 양력 생일도 가입 정보에 채웁니다. 음력·유형 미확인 생일과 유효하지 않은 번호는 가져오지 않습니다. 네이버도 제공된 이름·전화번호·생일만 사용합니다.
- 기존에 저장한 값·언어·테마·역할·승인 상태를 바꾸지 않습니다. 전화번호·생일의 빈 항목 보완은 거주 지역이 아직 저장되지 않은 가입 중 프로필에만 적용합니다. 거주 지역은 직접 입력하고 확인해야 하며, 가입 폼에서 수정 중인 항목을 늦게 도착한 정보로 덮어쓰지 않습니다. 생일을 공개 멤버 정보에 반영하는 것은 가입 폼 저장 후입니다.
- 카카오의 닉네임 제공에는 개발자 앱의 **닉네임 동의항목** 설정이 필요합니다. [설정 순서](LOGIN_SETUP.md#2-카카오-앱-설정)를 참고하세요. 제공되지 않은 이름을 이메일·사진·계정 ID로 추측하지 않습니다.

## 관련 코드

- `src/lib/social-auth.ts`: 제공자 설정 조회, challenge 생성, 로그인/연결 시작, 일회용 코드 교환
- `src/pages/AuthCallback.tsx`: `/auth/callback` 처리 및 쿼리 제거
- `src/components/AccountConnections.tsx`: 로그인 계정의 제공자 연결 상태
- `services/auth-worker/`: OAuth 제공자 콜백, 신원 연결, Firebase custom token 발급

카카오 캘린더 기능은 로그인 활성화와 별개의 권한·설정이 필요합니다. 로그인 코드가 준비됐다는 이유로 캘린더 전송이 활성화됐다고 표시하지 않습니다.

## 운영 확인

- `/config`의 `providers.kakao=true`, `providers.naver=false`, `calendar.kakao=true`를 확인했습니다. 캘린더 실제 사용 범위는 인증된 `/account/providers`의 `calendar.available`과 서버의 테스트 계정 제한으로 다시 확인합니다.
- 운영 로그인 화면의 카카오 버튼을 PC와 카카오톡 모바일 환경에서 확인했습니다.
- 카카오 계정 로그인 화면 진입까지 확인했으며, 실제 계정의 동의·연결 완료는 사용자가 직접 진행합니다.
- 기존 Google 사용자는 먼저 Google로 로그인한 뒤 **내 정보 → 계정 → 카카오 연결**을 진행합니다.
