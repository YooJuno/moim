# 모임

React + TypeScript + Firebase로 만든 모임 운영 사이트입니다. Google 로그인, 가입 승인, 게시판·사진첩, 시간대별 일정 투표, 캘린더, 장소·메뉴 투표, 자동 MVP 투표, 회칙, 회계를 제공합니다.

## 실행

```sh
npm install
npm run dev:demo
```

샘플 모임이 열립니다. 변경한 내용은 브라우저에 저장되며, 사진은 IndexedDB에 저장됩니다. 설정의 **샘플 데이터 초기화**로 처음 상태로 돌아갈 수 있습니다. 샘플 모드와 Firebase 데이터는 섞이지 않습니다.

```sh
npm run dev
npm run build
npm test
npm run test:e2e
```

`npm run dev`는 Firebase 환경 변수가 있으면 실제 서비스를 사용합니다. 모든 Firebase 값이 비어 있을 때만 샘플 모드가 됩니다. 일부 값만 있거나 Firebase 연결에 실패하면 오류를 표시합니다.

## 카카오·네이버 로그인

Google 로그인은 운영에 연결되어 있습니다. 카카오·네이버는 선택적으로 사용할 수 있는 인증 서버와 계정 연결 화면을 준비했습니다. 인증 서버는 Cloudflare Free에 배포했고 각 개발자 앱의 로그인 키 등록이 남아 있어 현재 Google만 활성화돼 있습니다. [설정 순서](docs/LOGIN_SETUP.md), [구현과 검증](docs/SOCIAL_AUTH.md)을 참고하세요. 앱 비밀키를 준비한 서버만 로그인 버튼을 표시합니다.

## Firebase 연결

기본 프로젝트 ID는 `moim-juno`입니다. 다른 프로젝트를 사용하려면 `.firebaserc`의 `projects.default`를 바꾸세요.

1. Firebase Console에서 웹 앱을 등록합니다.
2. `.env.example`을 `.env.local`로 복사하고 웹 앱 구성의 여섯 값을 입력합니다. `.env.local`은 Git에서 제외됩니다.
3. Authentication → Sign-in method에서 **Google**을 켭니다. Authorized domains에 로컬 주소와 운영 도메인을 등록합니다.
4. Cloud Firestore를 만들고 위치를 선택합니다. 운영 시작 전에 지역을 확인하세요.
5. 사진과 영수증은 압축본을 Firestore에 저장하므로 별도 Storage 버킷은 필요하지 않습니다.
6. 아래 배포 명령으로 Firestore 규칙·인덱스와 Hosting을 배포합니다.

Firebase 웹 구성은 브라우저에서 사용되는 식별 정보입니다. 서비스 계정 비밀키는 `VITE_` 변수나 클라이언트 코드에 넣으면 안 됩니다. 데이터 접근 권한은 Firebase Authentication과 규칙에서 검사합니다.

### 첫 관리자 등록

처음 Google 로그인한 사용자는 **가입 대기** 상태가 됩니다. 브라우저에서 스스로 관리자가 될 수 없습니다.

관리자 권한이 있는 Application Default Credentials를 준비한 뒤, 해당 계정을 관리자로 등록하세요. `firebase login`의 로그인 정보와 Admin SDK의 ADC는 별개입니다. 예를 들어 Google Cloud SDK가 있다면 다음과 같이 설정합니다.

```sh
gcloud auth application-default login
npm run bootstrap:admin -- --project moim-juno --email 사용자@gmail.com
```

또는 서버용 서비스 계정 자격 증명 경로를 `GOOGLE_APPLICATION_CREDENTIALS`에 설정한 뒤 스크립트를 실행합니다. 비밀키 파일은 레포 밖에 보관하세요. 스크립트는 Firebase Auth에 이미 존재하는 계정만 관리자로 등록하며, 기존 모임 이름과 회칙은 덮어쓰지 않습니다. 등록 후 새로고침하면 관리 화면이 열립니다.

ADC 없이 Firebase Console에서 지정할 수도 있습니다. 먼저 운영 사이트에서 관리자로 사용할 Google 계정으로 로그인합니다. Authentication → Users에서 해당 UID를 확인한 뒤 Firestore의 `members/{UID}` 문서에서 `role`을 `leader`, `status`를 `active`, `canCreatePoll`을 `true`로 변경하고 새로고침하세요. 본인 소유의 관리자 계정인지 확인한 뒤 지정합니다. 초기 모임 설정은 `settings/club`, 회칙은 `settings/bylaws`에 저장됩니다.

이후 가입 승인, 직책·권한 설정, 투표 생성 권한 부여는 **멤버** 화면에서 처리합니다. 모임 이름과 소개는 **설정**에서 바꿉니다.

### 게시판 사진

사진은 무료 요금제의 Firestore `photos/{id}`에 압축 이미지로 저장합니다. JPG·PNG·WebP·GIF를 장당 5MB, 게시물당 최대 8장까지 올릴 수 있습니다. GIF는 첫 프레임을 저장합니다. 사진을 압축해 약 450KiB 이하로 저장하며, 원본 파일을 보관하지 않습니다.

활성·승인 대기 계정이 읽을 수 있고, 업로드한 본인과 관리자만 삭제할 수 있습니다. 게시물에는 사진 ID만 저장합니다. 화면에 가까워진 사진만 가져와 로그인 세션 안에서 캐시하며, 로그아웃·계정 변경·승인 해제 시 캐시를 비웁니다. Storage 버킷이나 CORS 설정은 새 사진 업로드에 필요하지 않습니다.

과거 `storage:` 형식의 첨부 참조는 그대로 읽을 수 있도록 남겨 두었습니다. 별도로 Storage 버킷을 운영할 때만 `storage.rules`와 `storage.cors.json`을 적용하세요.

## 배포

```sh
npx firebase-tools login
npm run deploy
```

`npm run deploy`는 운영 빌드와 Hosting·Firestore 규칙·인덱스를 함께 배포합니다. `npm run deploy:demo`는 샘플 모드 빌드를 별도 review 미리보기 채널에 올립니다. `firebase.json`에 SPA 경로 재작성과 정적 파일 캐시 설정을 포함했습니다. `moim-juno`의 Firestore 기본 DB는 서울(`asia-northeast3`, Standard, 무료 등급)로 준비했습니다.

현재 사진과 영수증은 Firestore에 저장하므로 별도 Storage 버킷 없이 사용할 수 있습니다. 요금제는 변경하지 않았습니다. 게시물을 삭제한 뒤 남은 사진 문서는 관리자 데이터 도구에서 정리할 수 있습니다.

가입 대기 상태에서는 게시판·일정·투표 결과·회계 등 모임 내용을 열람할 수 있으며, 게시·댓글·투표·참석 응답 등 참여는 승인 후에 가능합니다. 거절된 계정은 콘텐츠에 접근할 수 없습니다. 역할이나 승인 상태는 본인이 올릴 수 없습니다. 본인의 활성 관리자 권한은 스스로 해제할 수 없으며, 다른 관리자를 먼저 지정하고 그 관리자가 변경하도록 합니다.

투표는 여러 후보에 응답할 수 있고 **가능한 시간 없음**도 저장합니다. 응답을 다시 저장하면 본인의 이전 응답이 갱신됩니다. 후보를 수정하면 유지된 후보 ID의 응답은 유지되고, 삭제한 후보의 응답은 집계에서 제외됩니다. Firestore 트랜잭션과 규칙이 마감·수정·응답 간 동시 변경을 검사합니다. 일정을 확정하면 캘린더 일정이 한 번만 생성됩니다. 확정 후 시간·장소 변경은 캘린더에서 합니다. 연결된 일정을 삭제하면 투표는 마감 상태로 돌아가고 기존 응답은 유지됩니다.

Google 캘린더는 일정 상세의 **Google 캘린더**에서 연결합니다. 관리자가 초대할 멤버를 고르고 실행하면 본인의 Google 캘린더에 일정을 만들고 선택한 이메일로 초대를 보냅니다. 연결한 관리자가 같은 일정을 다시 반영할 수 있으며, 사이트에서 수정한 내용은 해당 버튼으로 갱신합니다. 캘린더 연결 권한과 액세스 토큰은 브라우저 메모리에만 두고 Firestore에 저장하지 않습니다. 캘린더에 반영된 뒤 사이트 연결 정보만 저장에 실패한 경우 **연결 정보 저장**으로 다시 저장합니다.

각 일정에서 **장소·메뉴 투표**를 만들 수 있습니다. 후보의 이름·주소·메뉴를 입력하고, 멤버는 한 후보를 골라 투표합니다. 마감 전에는 선택을 바꿀 수 있고, 관리자가 장소를 확정하면 일정의 장소도 함께 갱신됩니다.

MVP 후보는 해당 일정에 **참여해요**로 등록한 멤버입니다. 별도의 후보 설정 없이 모임 종료 10분 전부터 투표가 열리며, 종료 후 24시간까지 한 명을 선택하거나 선택을 수정할 수 있습니다. 투표자도 해당 일정에 참여 등록한 멤버여야 합니다. 사이트를 열어 둔 참여자에게 투표 알림을 표시합니다.

무료 요금제를 유지합니다. 사이트를 닫은 상태의 자동 푸시·문자·카카오톡 알림과 서버 예약 발송은 포함하지 않습니다.

## 데이터 구조

- `members/{uid}`: 이름·이메일·생일의 월·일·역할·가입 상태·투표 생성 권한
- `profiles/{uid}`: 전화번호·거주지와 이전 생일 사본, 본인/관리자 전용
- `settings/club`, `settings/bylaws`: 모임 설정·회칙
- `posts/{id}`, `comments/{id}`: 게시물·댓글
- `polls/{id}`, `votes/{pollId_uid}`: 후보 시간·응답
- `events/{id}`, `rsvps/{eventId_uid}`: 확정 일정·참석 응답, 일정 종료 시각은 서울 시간 기준 `endAt`에 저장
- `ballots/{id}`, `ballotResponses/{ballotId_uid}`: 장소·메뉴 후보와 단일 선택 응답
- `mvpVotes/{eventId_uid}`: 모임별 MVP 선택, 참여자·투표 시간 조건은 서버 규칙에서 검사
- `ledger/{id}`: 수입·지출 내역
- `photos/{id}`: 압축한 모임 사진, 게시물에는 `photo:{id}` 참조만 저장
- `receipts/{entryId}`: 회계 내역의 첨부 영수증
- `places/{id}`: 자주 쓰는 장소
- Storage `members/{uid}/{id}`: 이전 형식의 첨부 참조만 유지

## 검증

프로덕션 빌드는 TypeScript 검사도 수행합니다. 브라우저 테스트는 샘플 모드에서 주요 사용자 흐름을 검증합니다. 실제 Firebase 프로젝트를 변경하는 테스트는 실행하지 않습니다.

보안 규칙 테스트는 Firestore 에뮬레이터에서 실행합니다.

```sh
npx firebase-tools emulators:exec --project demo-moim --only firestore 'npm run test:rules'
```

## 공휴일과 일정 입력

새 투표는 **다음 달 주말·공휴일, 08:00–24:00**을 기본으로 선택합니다. 취합할 월을 바꿔 다시 자동 선택하거나 날짜와 시간을 직접 수정할 수 있습니다. 달력에서 여러 날짜를 고르고 **공통 시간대**를 정합니다. 시간 선택은 **1시간 단위**이며, 클릭하거나 드래그해 선택·해제할 수 있습니다. 모든 선택 날짜에 같은 시간대가 적용되고, **날짜별로 다르게 설정**을 열면 특정 날짜만 바꿀 수 있습니다. 멤버는 시간대 안에서 실제로 가능한 구간을 각각 표시합니다. 투표 마감은 선택 사항이며, 마감 없음으로 두면 운영자가 직접 마감할 때까지 참여할 수 있습니다. 일정을 확정할 때는 같은 날짜의 연속된 구간을 골라 모임 시작·종료 시간을 정합니다. 공휴일은 이름과 함께 빨간색으로 표시됩니다. **결과 보기**에서는 같은 인원이 내내 가능한 연속 구간을 시작·종료 시각과 함께 모두 보여 줍니다. 기본 정렬은 오래 만나는 순이며 인원 많은 순으로도 바꿀 수 있습니다.

현재 **2018–2027년** 대한민국 공휴일 데이터를 포함합니다. 음력 설·추석, 대체공휴일, 선거일, 발표된 임시공휴일을 포함하며, 미지원 연도는 달력에 안내합니다. 신규 연도나 임시공휴일 발표 후 아래 명령으로 데이터를 갱신하고 다시 빌드하세요.

```sh
npm run holidays:update
```

데이터: 우주항공청 월력요항을 가공한 [holidays-kr](https://github.com/hyunbinseo/holidays-kr) (MIT, `src/data/holidays-LICENSE`). 임시공휴일은 발표 이후 데이터를 갱신해야 반영됩니다.

## 샘플 사진

데모 사진은 [Unsplash](https://unsplash.com)에서 제공한 이미지입니다. 산책 사진은 [Vitaly Gariev](https://unsplash.com/photos/uZrfnZ19-h4), 식사와 카페 사진은 [Unsplash 원본](https://images.unsplash.com/photo-1528605248644-14dd04022da1)과 [카페 원본](https://images.unsplash.com/photo-1517248135467-4c7edcad34c4)을 사용했습니다. 실제 모임 사진으로 교체할 수 있습니다.

개발 도구는 Node.js 22.12 이상(22 LTS·24 LTS·26)을 기준으로 합니다. 브라우저 테스트는 설치된 Google Chrome을 사용합니다. Firestore 규칙 테스트는 에뮬레이터가 없으면 건너뜁니다. Java 17 환경에서 검증한 명령은 다음과 같습니다.

```sh
DEBUG= npx --yes firebase-tools@14.12.0 emulators:exec --project demo-moim --only firestore 'npm run test:rules'
```

샘플 저장소를 사용하지 않는 Firebase 통합 브라우저 테스트도 있습니다. 별도의 `demo-moim` Auth·Firestore 에뮬레이터와 5174번 Vite 서버를 띄워 실제 SDK로 글 수정, 투표 수정·마감·재개·확정, 가입 대기자의 프로필 저장을 검증합니다. `.env.emulator`는 가짜 설정만 포함하며 실제 Firebase 프로젝트에 연결하지 않습니다.

```sh
DEBUG= npx --yes firebase-tools@14.12.0 emulators:exec --project demo-moim --only auth,firestore 'npx playwright test -c playwright.firebase.config.ts'
```

## 명부와 가입 계정 연결

관리자는 Google 가입 전의 멤버도 명부에 등록할 수 있습니다. 명부 등록은 로그인 계정을 만들지 않으며, 운영 직책과 사이트 권한은 별도로 관리합니다. 직책은 없음·회장·부회장·총무 중에서 선택합니다. 직책을 바꿔도 사이트 권한인 관리자·회계 담당·일반은 바뀌지 않습니다.

등록된 멤버가 Google로 가입하면 관리자가 가입 대기 계정과 기존 명부를 직접 연결합니다. 가입 계정의 UID·이메일·기존 사이트 권한·가입일은 유지하고, 명부의 이름·직책·개인 정보를 옮긴 뒤 중복 명부를 삭제합니다. 이름이 같다는 이유로 자동 연결하지 않습니다.

생일은 연도 없이 `MM-DD` 형식으로 저장합니다. 전화번호·거주지는 본인과 관리자만 조회할 수 있습니다. 생일의 월·일은 모임 열람 권한이 있는 계정에게 공개되어 홈과 캘린더에 표시됩니다. 실제 명부는 Firestore에만 저장하고 샘플 데이터에 포함하지 않습니다.

## 회계 영수증

관리자와 회계 담당자는 회계 내역에 영수증 사진 한 장을 첨부·교체·삭제할 수 있고, 활성·승인 대기 계정은 첨부한 영수증을 볼 수 있습니다. JPG·PNG·WebP 파일을 5MB 이하로 올리면 긴 이미지를 포함해 최대 1200×2400 크기, 약 450KiB 이하로 압축합니다. PDF는 지원하지 않습니다.

영수증은 별도 `receipts/{entryId}` 문서에 저장하고 열 때만 가져옵니다. 회계 목록에는 첨부 여부만 저장합니다. 내역 수정 시 기존 첨부를 유지하고, 내역 삭제 시 영수증도 함께 삭제합니다. 사진 문자열의 인덱스는 제외했습니다. 샘플 모드의 영수증은 IndexedDB에 저장됩니다. 별도 Storage 버킷이나 유료 요금제는 사용하지 않습니다.

## 자주 쓰는 장소

관리자는 장소 이름과 주소를 저장·수정·삭제할 수 있습니다. 저장한 장소는 일정과 장소 투표를 만들 때 선택하며, 해당 시점의 이름·주소를 복사합니다. 저장 목록에서 장소를 바꾸거나 삭제해도 이전 일정의 장소 기록은 유지됩니다. `places/{id}`는 활성·승인 대기 계정이 읽고 관리자만 변경할 수 있습니다.

## 관리자 설정과 내 정보

모임 이름·대표 사진과 저장 장소 관리는 관리자 전용 `/settings`에서 합니다. 개인 프로필·연락처·생일·로그아웃은 `/profile`로 분리했습니다. 일반 멤버에게는 모임 설정 메뉴가 표시되지 않으며 직접 경로로 접근해도 관리자 설정을 열 수 없습니다.

직접 요청한 기존 명부는 삭제했으며, 이후 실제 가입한 계정은 유지합니다. 기존 외부 명부를 자동으로 다시 등록하지 않습니다.

## 개인 설정과 주소·지도

내 정보에서 한국어·영어와 시스템·라이트·다크 화면 모드를 선택합니다. 개인 프로필에 저장하며 연락처·생일과 별개로 보존합니다. 생일은 월·일 선택기로 입력하고 출생 연도는 받지 않습니다. 우측 프로필 아이콘은 내 정보·로그아웃 메뉴를 엽니다.

장소·일정 입력의 주소 검색은 무료 카카오 우편번호 서비스를 쓰며, 직접 수정할 수도 있습니다. `/places`에서 자주 가는 장소를 열람하고 Google 지도 보기·길찾기를 열 수 있습니다. 지도 URL 방식으로 별도 유료 Maps API를 사용하지 않습니다. 관리자만 장소 목록을 관리합니다.

## 일정 문자 알림

Cloudflare Free Worker와 SOLAPI 연결을 마쳤습니다. 모임 설정에서 문자 사용을 켜면 관리자만 일정 상세의 미리보기로 대상·문구·예상 비용을 확인하고 유료 발송할 수 있습니다. 자동 발송까지 켜면 일정 투표 확정 직후 대상에게 접수합니다. 기본값은 꺼짐이며 실제 문자는 개발 도구로 발송하지 않았습니다. 설정과 결과 확인은 [SMS_SETUP.md](docs/SMS_SETUP.md)를 참고하세요.
